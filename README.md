# Celeste mode for RetroBat

NES games played the Celeste way:

* Each game is cut into checkpoints, a few per stage. Any hit is a death,
  and a death sends you back to the last checkpoint.
* Whenever I could make it work, music doesn't stop when you die, for a better flow as in Celeste
* EASY has the most checkpoints and HARD the fewest. On EASY a hit in a
  boss room only costs health; dying still sends you back to the start of
  the fight. MEDIUM adds checkpoints at 75, 50 and 25 % of a boss's health
  and HARD one at 50 %.
* The lives counter counts the deaths.

There will be issues here and there, please report or submit fixes. I've done a bit of manual curation on the Megaman games because it's the ones I like the most, try these first for the best experience.

## Installation:

* Close Retrobat/Emulation Station
* Download the zip from [Releases](../../releases)** and extract
* Run the installer
* Start Retrobat


The installer asks for your RetroBat folder, checks that what Celeste mode
needs is there, and sets up the rule files for the NES ROMs you have that
it supports, the system that plays them, and its logo and background in
your themes. It looks for the ROMs in `roms\nes` (and its subfolders, and
its gamelist), finds each game by its name, then checks its checksum: only
the exact version in the compatibility list below is installed.

The uninstaller cleans up everything. 

## Controls

On a DualSense; on another pad, the buttons in the same places (○ is the
right face button, △ the top one):

* **L1**: back to the checkpoint before the last one, your deaths kept.
* **Hold ○ for 1 second**: a hit no longer sends you back, you just lose
  health as in the normal game (losing a life still sends you back).
* **Hold △ for 1 second**: back on, every hit sends you back again.

For megaman games pressing select on the robot master selection screen will give you all weapons and activate late stages, sometimes pressing a second time brings you even further (Mega Man 3: Break Man, then Wily's castle, in the centre square; Mega Man 6: from Mr. X's fortress map to Wily's castle).

## How it works

- `runtime/launch.ps1` is the celeste system's command. It starts the game
  through RetroBat's emulatorLauncher with RetroArch, then runs the watcher
  (`runtime/Celeste.cs`, compiled by PowerShell at launch) beside it.
- The watcher reads the game's RAM through RetroArch's network commands
  (`READ_CORE_MEMORY`, or `READ_CORE_RAM` for a core without a memory map:
  every SNES core), takes a save state at each checkpoint it reaches,
  and on a death loads the last one.
- `roms/celeste/*.yaml` are the rule files, one per game: which bytes are a
  hit (health, lives, a death state), the pad, the music to carry across a
  rewind, and the checkpoints. Each game's checkpoints were cut from a
  TASVideos run replayed on the one exact ROM the file is for; its comments
  say how each address was checked.
- `runtime/PadAudio.cs` finds DualSense pads for the hold-to-switch buttons.

## A rule file, explained: Mega Man 2

Each supported game has one rule file in `roms/celeste/`. It tells the
watcher which bytes of the game's RAM to read, and what to do when they
change. Here is Mega Man 2's, simplified; the full file, with the comments
that say how each address was checked, is
[roms/celeste/Mega Man 2 (USA).yaml](roms/celeste/Mega%20Man%202%20(USA).yaml):

```yaml
variables:
  0x0023: Pad
  0x002A: Stage
  0x00A8: Lives
  0x0400: Sprite
  0x0440: Screen
  0x055E: Song
  0x0580: PlayerFlags
  0x06C0: Health
  0x06C1: BossHealth
name: Mega Man 2 (USA)
rom: nes/Mega Man 2 (USA).nes
hit:
  - "PlayerFlags changed && PlayerFlags == 0x41 && Song was < 0xAC"
  - "Health decreased"
  - "Lives decreased"
lives: Lives
lives_floor: 2
input: Pad
input_bits: a b select start up down left right
keep:
  - 0x0500-0x05FF
song: "Song & 0xFC"
mode: checkpoints
checkpoints:
  - name: Quick Man start
    when: "Stage == 0x04 && Screen == 0x00 && Sprite was 0x1A && Sprite != 0x1A"
    start: yes
  - name: Quick Man 10
    when: "Stage == 0x04 && Screen changed && Screen == 0x09"
    levels: easy
  - name: Quick Man 22
    when: "Stage == 0x04 && Screen changed && Screen == 0x15"
    levels: easy medium
  - name: Quick Man boss room
    when: "Stage == 0x04 && Screen changed && Screen == 0x17"
    wait: 0
    no_rewind: easy
```

**`variables`** names the addresses the rest of the file uses: `Health`
is the byte at `0x06C0`.

**`name` and `rom`** are the game as RetroBat knows it: the name it shows
in the game list, and the ROM's path under RetroBat's `roms` folder. The
installer looks for a ROM by that name first, then checks its checksum: a
rule file only works on the exact ROM it was made for.

**`hit`** is the list of what counts as a hit. Any one of them being true
is a death: the watcher loads the last checkpoint at once, before the game
has time to play its death. Every condition compares the byte as it is
now with the read before it (the watcher reads the RAM many times a
second):

- `Health decreased`: Mega Man's health went down. Any damage, however
  small, is a death, as in Celeste.
- `Lives decreased`: the lives went down. A pit takes no health, so this
  catches it when the health rule cannot; it is the safety net.
- `PlayerFlags changed && PlayerFlags == 0x41 && Song was < 0xAC`: the
  player's state just became 0x41, the value it takes the instant Mega
  Man dies, falls included. It catches a pit at once, instead of waiting
  ~4 seconds for the lives to drop. `&&` joins clauses that must all be
  true.

A clause is `<address> changed`, `unchanged`, `decreased`, `increased`,
`decreased by <n>`, `was <value>` or `was <comparison>` (the read before
this one), or a comparison with `==`, `!=`, `<`, `<=`, `>`, `>=` against a
number. Numbers are hexadecimal with `0x`, or decimal.

**`lives: Lives`** is the game's lives counter. With the COUNT LIVES
option on, the watcher writes the number of deaths there, so the HUD
shows how many times you died instead of how many tries you have left,
and the game never runs out of lives.

**`lives_floor: 2`** is the lowest number ever written into that byte. In
Mega Man 2 the byte counts the life being played: 1 already means "last
life", and losing it would be a game over. So the counter starts showing
from 2.

**`input: Pad`** is the byte where the game keeps the buttons held, and
`input_bits` names its bits. The watcher arms on the first real button
press, so the title screen's demo is never mistaken for a death. Some
games also get a button patch: in Mega Man 2, Select on the stage select
gives every weapon and opens Wily's castle.

**`keep: 0x0500-0x05FF`** is the music player's memory. Without it, every
death would also rewind the music. Copied over the loaded save state, the
music plays on as if nothing happened. Each range was checked to hold
only music: keeping it must change nothing else in the game.

**`song: "Song & 0xFC"`** is the number of the song playing. The music is
carried across a rewind only when this byte reads the same now and in the
save state; `& 0xFC` compares only the bits that name the song. The
CONTINUOUS MUSIC option needs both `keep` and `song`.

**`checkpoints`** is the list, in the order of play. A checkpoint counts
when its `when` turns true, the first time play gets there; it is then
saved 2 seconds later, once the player has shown they can stand there
(`wait: 0`: at once, for a door or a boss room). `start: yes` is a
stage's start, which counts in any order. `levels` limits a checkpoint
to some of EASY, MEDIUM and HARD (all three when left out). `no_rewind:
easy` makes it a free zone on EASY: from there until the next checkpoint
a hit only costs health, and a death goes back to it. The boss thresholds
(`Wood Man boss 75%` and so on) are checkpoints too, on the boss's health.

Every key but `name`, `rom` and `hit` is optional; the compatibility list
above shows which games have what.
